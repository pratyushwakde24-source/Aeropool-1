## 2. Threat Vector Review & Mitigations

### 2.1 Authentication & JWT Integrity (OWASP API1 / API2)
* **Mechanism:** Token verification in `server/authMiddleware.ts`.
* **Verification:** Tokens are validated against Supabase Auth endpoint `/auth/v1/user`. Self-signed or tampered JWTs are rejected with `HTTP 401 Unauthorized`.
* **Privilege Escalation Defense:** User roles (`passenger`, `driver`, `fleet_operator`, `admin`) are extracted **strictly from protected `app_metadata`**. Any role claims passed in user-editable `user_metadata` or client HTTP request bodies are strictly ignored.
* **Session Expiration:** Stale tokens return `401 Unauthorized`, prompting seamless frontend token refresh via the Supabase Auth client without redirect loops.

### 2.2 Broken Object Level Authorization / BOLA (OWASP API1)
* **Passenger Bookings:** Passenger endpoints verify that `req.user.id === booking.passengerId`. Cross-passenger booking inspection is rejected (verified in automated Test 8).
* **Driver Ledger:** Drivers can query only ledger entries where `driverId === req.user.id`.
* **Admin Endpoints:** Privileged financial and reconciliation routes enforce `requireRole(['admin'])`. Non-admin requests are rejected with `HTTP 403 Forbidden` (verified in automated Test 160 and live curl probe).

### 2.3 Webhook Authenticity & Tamper Proofing (OWASP API8)
* **Signature Verification:** Razorpay webhook payloads are verified using HMAC-SHA256 over raw unparsed request bytes (`express.raw({ limit: '256kb' })`).
* **Timing-Attack Resistance:** Signature comparison utilizes `crypto.timingSafeEqual` in `safeCompareSignatures()`.
* **Monotonic State Machine Guard:** An order in `PAID` or `REFUNDED` status cannot be downgraded by out-of-order or delayed failure events (e.g. `payment.failed`).
* **Idempotency:** Webhook event IDs are tracked in `idempotencyStore.ts`. In-flight processing locks prevent duplicate processing under high concurrency.

### 2.4 Sensitive Data Exposure & Credential Scrubbing (CWE-312)
* **Payload Scrubbing:** Webhook payloads stored for failure recovery or displayed in the Super Admin modal undergo recursive redaction. Sensitive keys (`card`, `cvv`, `number`, `token`, `secret`, `password`, `auth`, `pin`) are replaced with `[REDACTED]`.
* **Client Bundle Hygiene:** `server/envValidator.ts` inspects environment variables on boot and halts if any server secret (`DATABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RAZORPAY_KEY_SECRET`) begins with `VITE_`.
* **Log Redaction:** `maskSecret()` ensures that credentials printed during startup diagnostics display only leading/trailing characters (e.g. `rzp_...6789`).

### 2.5 File Upload Validation & KYC Security (CWE-434)
* **Remediation in Phase 6:** `DriverKYCView.tsx` was hardened with strict client-side validation:
  1. **MIME Whitelist:** Restricts photo uploads to `['image/jpeg', 'image/png', 'image/webp']`. Executables and shell scripts (`.exe`, `.sh`, `.bat`) are rejected immediately.
  2. **Size Boundary:** Restricts file sizes to 5MB (5,242,880 bytes).
* **Cloud Storage Access Control (Medium Finding):** In the production deployment, the Supabase Storage bucket `driver-kyc-documents` must have public read access disabled (`public: false`), serving documents only via short-lived signed URLs generated by authorized Super Admin requests.

### 2.6 CSV Formula Injection Protection (CWE-1236)
* **Threat:** Malicious passengers or drivers entering names or identifiers starting with spreadsheet formulas (`=cmd|' /C calc'!A0`, `@SUM(...)`, `+`, `-`).
* **Mitigation:** In `server/orderStore.ts`, `sanitizeCsvField()` checks for dangerous prefix characters (`^[=+\-@\t\r]`) and prepends a single quote (`'`), neutralizing spreadsheet execution in Microsoft Excel and Google Sheets. Verified in automated Test 167.

### 2.7 Cross-Origin Resource Sharing (CORS) & Security Headers
* **CORS Policy:** Strict `ALLOWED_ORIGINS` enforcement in `server/index.ts`. Wildcard origins (`*`) are disallowed in production mode.
* **HTTP Security Headers:**
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY` (Clickjacking prevention)
  - `X-XSS-Protection: 1; mode=block`
  - `X-Correlation-ID` header attached to every response for distributed tracing.

### 2.8 Rate Limiting & Denial-of-Service Defense
* **Payment Order Limiter:** 10 requests / minute per IP.
* **Payment Verification Limiter:** 20 requests / minute per IP.
* **Privileged Admin Limiter:** 60 requests / minute per IP.
* **Body Size Limits:** JSON bodies restricted to 100kb; webhook payloads restricted to 256kb.
* **Request Execution Timeout:** 15-second timeout middleware terminates runaway requests with HTTP 504.
